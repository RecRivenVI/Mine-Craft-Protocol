# 扩展平台验证

验证以当前候选的实际包、SDK、Loader 和输入哈希为准，研究原型与开发者预览证据不代替新平台运行证明。

## 层次

先检查清单/内容审批、依赖与事务、实例级注册隔离和 owner 清理，再在参考 Target 打通实际 Provider/探针；早期 Mixin、五端成品安装、独立服务端和第三方业务分别验证。

每个场景明确假设、否证条件、固定输入、调试准备、正常 Act、独立 Assert、证据与 Cleanup。必须验证实际结果，不能以 click completed、方法计数或 Debug 写成功替代业务效果。

## 负向与清理

覆盖未批准/替包、重复类、循环依赖、缺模组、错运行端、初始化抛错、schema 不符、预算、超时、取消、旧资源版本、失效 Arm/Lease、换 Screen/世界、连接关闭及 Runtime shutdown。

故障链至少包含两个不同包分别失败、分别恢复；关闭每项资源独立记录，owner 拒绝或线程已停止不能报告清理成功。活动世界拒绝复制，停机后核对进程、端点与文件锁再快照。

## 运行约束

只通过 Mine-Craft-Protocol Native HTTP/WebSocket 或 MCP 操作游戏，禁止 Computer-Use 和宿主输入注入。自动实例1920×1080静音、最大4GiB。物理 Esc、系统焦点、真实 IME 和视觉验收留在统一真人清单；自动测试不能冒充真人证明。Persistent Write 为0，不运行整合包或性能基准。
