# Mine-Craft-Protocol 当前执行计划

当前只执行用户批准的整理阶段一：产品总览、研究资料归位与仓外清理。完成后停止，等待真人验收及后续开发安排；不是产品阶段二，也不恢复旧Goal。

## 目标

用可读入口解释完整产品、现状与边界，分开已实现、自动证明、真人待验、已确认未实现和研究设想；让四类研究和活输入可定位，实际回收已核清的再生产物。

## 范围

- 仓内只修改产品总览、当前状态、当前计划和必要入口链接，所有总览链接均为仓内相对链接。
- 仓外建立ExploratoryDebug、AutonomousPlay、RenderForensics、SecondPlayer专题入口；跨专题材料只有一个原件。冻结报告、源码/补丁、输入身份、Fixture、捕获、失败、基线和旧快照保持原址原文。
- 活Dependencies/Inputs/ExtensionInputs、全部Alpha及使用登记、当前验收、必要预览、使用方反馈和支撑结论的原始调查不回收。
- 目录清点使用Everything；按归属、活引用、保留价值和必要哈希确定准确回收对象。不穿透链接，不触碰其他项目、生产实例、世界、凭据或工作区Archives/Backups/References。
- 只将核清对象送Windows回收站；占用、未知或无法安全回收的对象保留。仓外Organization说明集中记录原址、专题入口、去向和处置结果，体积区分活动目录减少与同盘回收站占用。
- 零业务代码改动，不改Runtime/组件/适配/测试/协议/依赖/产品配置/构建/模板，不构建、不启动实例、不测试产品、不重新发包。
