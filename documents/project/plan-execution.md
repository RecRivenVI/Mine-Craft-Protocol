# Mine-Craft-Protocol 当前执行计划

当前授权为1.0扩展平台正式实现，基线develop/4346328d与固定Alpha 20261031-1440-d6f3a89a。开发者预览自动收尾保留，其集中真人验收仍待用户安排，不阻塞本计划。

## 目标

把公共SDK、五端Loader桥、独立适配包、统一测试/探针和MCP查阅接入现有Runtime，形成可安装、可诊断、可清理、可实际操作的完整成果。1.0是内部质量标准，不是公开发行决定或长期外部兼容承诺。

## 范围

- 按用户批准研究方案及六项默认值实装，原型仅参考，不直接合入；当前阶段和门禁统一见[状态页](status-milestones.md#当前工作与下三步)。
- 普通ZIP/目录、内容身份本地审批、固定依赖与Target/运行端入口；不远程上传代码，不自动下载缺失依赖，代码更新重启。
- SDK不依赖Minecraft，Target桥负责原生Loader/客户端/服务器差异；复用现有授权、Provider、Debug、输入、资源版本、证据与测试，不新增Lease。
- UI深入真实hover、click、drag、多按钮、scroll、文本/IME及可见投影；世界复用普通目标，复杂部件合同保持预览，缺口如实声明。
- 首批CC、Create、AE2、EMI、Exposure、Modern UI、LittleTiles独立包；作者工程暂放tool组件components/extension_packages，不新建远程仓库，不将包合进本体。
- 静态作者规则/合同可离线查阅；安装包目录与文档无需世界DEBUG读取权，游戏数据仍独立授权。主机编排先由验证工具消费登记ID，权限与Runtime分离。
- 不做整合包测试、E1/E2/E3、Persistent Write、性能基准、Fake Player、第二游玩界面或平台以外新功能。

## 验证与协作

阶段门禁通过后直接进入下一阶段，不等用户逐项批准；普通实现细节自主决定，产品疑点先选可撤回方案，无法安全继续才询问。
中途允许按既有规则创建Update检查点：仅标题、无正文、SSH签名、提交日期等于作者日期，正常推送develop，不建tag、不强推。中途不刷新Alpha。
普通验证一次一个自有客户端，可配自有服务器；双玩家组仅在测试明确需要时使用两客户端。自动客户端1920×1080静音、最大4GiB；人工实例按约定2560×1440、RecRivenVI及附加Mod。
不使用Computer-Use、桌面自动化或宿主输入注入，不操作Prism或用户重要存档；使用用户既有EULA授权。停机、端点和锁确认后才复制/回收自有实例。
研究证据与本轮产品证据分开；五端各自运行，不以一端结果代替其他端。缺版本、未实现、明确拒绝、测试失败和未人工验收分别记录，不把预览当作无诊断/无清理的借口。
按实际修改执行相关验证；共享代码及阶段冻结时跑五端回归，候选改变只重跑受影响组和共同安全检查，不无意义重跑未变化路径。
