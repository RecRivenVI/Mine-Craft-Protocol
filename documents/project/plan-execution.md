# Mine-Craft-Protocol 当前执行计划

当前目标是 UI 首个里程碑 READY、世界首个里程碑 READY 与功能 Showcase READY，随后交给用户验收并停止。
三个目标均尚未完成；READY 不等于最终人工 PASS。本文件只描述当前计划，不追加流水记录。
当前按用户要求暂停任务与Goal，等待项目规划调整；以下未完成步骤不自动执行，不启动新功能或人工验收。
用户已于2026-10-18单独授权打包并推送当前项目成果；此授权不恢复开发目标，新的模式/权限建议尚未实施。
恢复开发先读[唯一当前状态页](status-milestones.md)：工作包×五Target状态、最近证据、剩余规模和下三步只在该页维护。

## 目标

以 Core 的 Agent-native Minecraft Autonomous Testing Platform 为交付边界，
让 Agent 经正式 Native/MCP/网页接口完成发现、真实操作、等待/断言、诊断、采证和清理。
完成两个领域的必需操作目录、五端当前候选验证及可重复展示集合，不以代表用例替代全目录。

## 范围

- 按[Core](scope-core.md)、[控制模型](../design/concept-agent_control.md)、[世界目录](../design/concept-world_control.md)
  和[原版UI目录](../development/testing-vanilla_ui.md)执行 M-01～M-12；WU-01～WU-20、WD-01～WD-12 是有限家族，不扩成所有参数、物品或种子的笛卡尔积。
- UI USER 仅用户可见且可正常操作；世界 USER 是有界客户端模型，不自动加载区块、不开放服务器内部数据。
  TAKEOVER 只走真实玩家输入，OPERATE 只走批准的 typed DEBUG；模式不授予 scope、Lease 或 Arm，证据权威保持独立。
- M-09 首个里程碑只交付三部署设计定稿、权限主体模型、安装/合规表达及现有 Peer 范围的双端联动。
  独立服务端 Runtime、零玩家控制台和完整仅服务端能力属于下一里程碑，分配只见[部署设计](../design/concept-deployment_scenarios.md)及状态页。
- 对 Structure/Test 等不透明管理效果、函数/调度、来源不明复制，发送前拒绝、零相关服务器副作用和明确限制即可关闭对应必需分支；
  不能将未接守卫或未实测的拒绝写成通过，也不能将原生先保存造成的部分提交说成零修改。
- 首次 Developer Preview 只交付 Core；[E1/E2/E3](scope-extensions.md)可延期或取消，不阻塞 Preview。
  Persistent Write、安全基础后的正式写入审查、Phase 9E/9F/9G/10、整合包测试、寻路及 Render Forensics 不在本目标内。
- 保留用户工作树，未经明确授权不暂存、不提交、不推送、不建 tag；本次仅按用户授权打包现有成果，不扩展开发。只操作本线程隔离实例，默认一次一个客户端、4 GiB 最大堆；禁止 Computer Use、宿主输入模拟及外部 Prism/重要存档操作。

M-11展示集合已达到V；M-03的Toast增量已五端专项通过，M-01的正式分类目录和读取消费者隔离已闭合。
本轮收尾后暂停；恢复时先按用户的新规划确认下列未完成工作包，不以暂停改写已有实现成果。
总范围与完成条件不变，第三方覆盖及未来扩展API只登记，不将第三方实验后端纳入产品。

1. 进行中：M-01，01a正式Native/MCP、条件/Provider分类目录及01b读取消费者隔离已完成；01c现有Peer授权落点待与M-09合测，不以目录关闭代替整个权限包完成。
2. 进行中：M-02，按五端实际原版 UI 目录补齐 USER 语义发现、操作及独立行为，先覆盖尚缺家族，再加深边界；不从类继承或单端结果推定其他端。
3. 进行中：M-03，五类setter/完整文本守卫、书本/告示牌及Native/MCP调试与网页USER消费者边界已五端闭合；继续特殊菜单/呈现的合法字段目录，不调用任意内部对象补目录，也不将网页USER入口伪称DEBUG编辑器。
4. 进行中：M-04，补剩余 HUD/Toast 呈现、多人玩家列表边界与 USER/DEBUG 投影；原生缺席须有版本事实，不将未验写成只读或不适用。
5. 进行中：M-05，完成 WU-01～WU-20 的感知、真实玩家输入、效果/拒绝与清理，优先移动/载具、物品/实体及维度/重生剩余独立家族，不实现自动寻路。
6. 进行中：M-06，逐项核对 WD-01～WD-12 已批准字段与 typed 操作，补缺失能力或有依据的原生只读边界，不以玩家命令代替正式 DEBUG 目录。
7. 完成：M-07，命令/管理提交与未知回调、间接程序/复制按发送前拒绝及明确限制收口；保留Jigsaw前序配置的部分提交真值，不继续深化模板或程序解析。最终候选复验归M-10，完成不等于整个领域READY。
8. 进行中：M-08，对新增场景继续使用版本专属不可变基准，校验恢复哈希、完整文件集合、凭据隔离和生命周期锁，不无故重建已确认基准。
9. 进行中：M-09，定稿首个里程碑部署设计与安装限制，落实现有 Peer 接收端的主体、授权、版本/身份及撤权/断线检查，完成既有双端目录验收。
10. 进行中：M-10，五端独立发行JAR的全新Loader安装已作为每次alpha刷新硬门禁；最终候选冻结时仍需完整领域、消费者、取消/隔离及端口/进程矩阵，开发classpath不代替制品安装。
11. 完成：M-11，功能展示集合、Arrange/Act/Assert/Evidence、恢复说明与五端17项自动执行已收口，支持 Target/单例/All/保持时间/保留客户端；最终候选参加M-10复验，真人 Esc/焦点独立未执行，不冒充视觉PASS。
12. 待办：M-12，复核所有必需项和真实限制，生成匹配源码、五端 alpha JAR 与证据的清单/Agent手册，准备人工步骤；仅在两领域及 Showcase 均 READY 后结束目标。

每个增量先在参考端及受影响 Target 执行相关回归；每三个增量、共享代码变化或候选冻结时跑五端完整矩阵并刷新 alpha/手册。
当前收口顺序、各包带编号的剩余验收组和粗估工时只在状态页维护；优先把最接近完成的包推到V，
每关闭一包立即更新该页，不以反复深化单一管理型边界代替广度完成，也不将V冒充READY。
刷新验证成功后按[固定分发工作流](../development/workflow-alpha_agent.md#固定分发与使用登记)发布同批七文件快照，再更新latest.txt；
其他线程只复制固定快照，不引用build/。保留最近三份和登记在用的批次，不覆盖已发布内容；这不扩大里程碑范围。
同一失败无实质改动最多重试三次；有界定位原因，不降低断言、不吞错误、不拼接不同候选结果。
游戏运行与 Gradle 构建串行，运行有 deadline；只关闭确认属于本线程的进程。当前权限合同不足以决策时保留原合同，提出最小决定点。
